# ゲームUIデザイン知見・ノウハウ集

デザイナーとエンジニアが効率的に連携し、高品質なゲームUIを制作するための知見をまとめています。

## 1. レイアウト設計のロジック

### 固定アスペクト比（9:16 ステージ方式）
- **理由:** Webサイトのようにスクロールが発生すると、情報の密度が下がり没入感が削がれる。全ての要素を1画面に収めることで、ゲームとしての「手触り」を均一化する。
- **実装:** `max-width` と `aspect-ratio` を組み合わせ、PCでもスマホでも「メインステージ」のサイズ感を一定に保つ。

### アンカーポイントの固定
- **ルール:** UI要素をブラウザの端（Viewport端）ではなく、常に「ステージの端」を基準に配置（Absolute Positioning）する。
- **メリット:** 画面サイズが変わってもUI同士の相対的な距離が変わらず、デザイナーの意図したレイアウトが崩れない。

## 2. 視覚的演出（Juicy UI）

### ネオン・発光演出
- **テクニック:** `box-shadow` や `drop-shadow` を複数重ね掛けする。
- **ロジック:** 背景が暗いため、光源を意識した発光を足すことで、平坦なUIに奥行きと「生きている感」を出す。

### 3. 動的フィードバック
- **Framer Motionの活用:** カードの傾き（Tilt）、ホバー時のスケール、ボタンのバウンスなど。
- **言語化:** 「ふわっと動かす」ではなく、「イージングは `easeOut`、持続時間は `0.3s`」といった具体的な数値でエンジニアと共有する。

## 3. デザイナーとエンジニアの共通言語

### Tailwind CSS の活用
- デザイナーが Figma で定義したカラー（例：Cyan-500）や角丸（例：rounded-xl）を、エンジニアがそのままクラス名として利用。
- スタイルガイド（`style_guide.md`）に共通の定義をまとめることで、実装のズレをなくす。

## 4. アセット管理
- **アイコン:** 常に `SVG`。コードに埋め込むことで色やサイズの変更をエンジニア側で容易にする。
- **画像:** 透過と軽量化の両立のため `WebP` を推奨。
