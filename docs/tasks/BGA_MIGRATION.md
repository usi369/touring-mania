# BGA対応: Board Game Arena移植に向けた実現可能性調査・設計

## 背景

Touring ManiaをBoard Game Arena（BGA）へ移植できるか検討する。

現行版はReact、tRPC、Cloudflare Workers、D1で構築されている。一方、BGA
StudioではBGA固有のPHPバックエンド、ゲームステート管理、通知、DB、UI規約に
合わせた実装が必要となる。

単純なデプロイ先変更ではなく、BGA版の再実装プロジェクトとして扱う。このタスク
では実装着手前に技術、ルール、権利、運用上の課題を整理し、移植方針と作業範囲を
確定する。

## 現行版から再利用できるもの

- Touring Maniaのゲームルール
- 152枚のバイクカードマスター
- 4タイトルごとの収録カード情報
- CPU判断ロジックの考え方
- 画面構成、演出、カードデザインのコンセプト
- 現行実装に含まれるルール判定とカード重複防止ロジック

## 主要な懸念事項

### 1. バックエンドの再実装

- TypeScript、tRPC、Cloudflare Workers、D1の処理をBGAのPHPゲームクラスへ移植する
- D1のテーブル構造をBGA管理DB向けに再設計する
- React側に分散している進行制御をサーバー側へ集約する
- アクティブプレイヤー、操作権限、ゲーム状態を全操作でサーバー検証する

### 2. ゲームステートの再設計

以下をBGAのステートマシンとして定義する。

- ゲーム開始と配札
- ダイスと宣言者決定
- 手札確認
- スペックと高い順・低い順の宣言
- カード選択と複数枚出し
- 縛り宣言
- ドローとパス
- 次プレイヤーへのターン遷移
- 場流れとラウンド終了
- 順位確定とゲーム終了
- 切断・退出プレイヤーのzombie処理

### 3. 非公開情報の管理

- 現行`game.getState`は全プレイヤーの手札IDを返すため、そのまま使用できない
- 各プレイヤーの手札は本人だけに送信する
- 観戦者、リプレイ、再接続時にも非公開情報を漏らさない
- 公開データ、プレイヤー個別データ、通知データを分離する

### 4. リプレイと再接続

- すべての操作をBGA通知として再現可能にする
- 再読み込み、再接続、途中観戦で盤面を完全復元する
- Reactのローカルstateだけに存在する状態を整理する
- アニメーションをリプレイ時にスキップまたは再現可能にする

### 5. CPU対戦

- BGAで一般的なAIプレイヤーを扱える範囲を調査する
- 現行`cpuPlay`を通常プレイヤーとして移植できるか確認する
- 初期版を対人戦限定にするか、Automa・練習モードを別設計するか決定する

### 6. フロントエンドとUI

- React、Framer Motion、Radix UI、Tailwindの再利用範囲を調査する
- BGA標準のプレイヤーパネル、ゲームログ、チャット、ヘッダーと共存させる
- 固定9:16から、PC・タブレット・スマートフォン向けの盤面へ再設計する
- 独自ログ、スコアボード、トーストとBGA標準機能の役割を整理する
- 長い演出や自動モーダルに短縮・スキップ手段を用意する
- 色だけに依存しない表示、タップ領域、可読性へ対応する

### 7. ゲームルール移植

- 高い順・低い順の比較
- 前ラウンドと同一の宣言禁止
- 同値カードの複数枚出し
- メーカー、気筒数、AT・MTの縛り
- 山札カテゴリとドロー
- パス、場流れ、デッドロック
- 2～4人のターン順、脱落、順位確定
- 手札、山札、場札におけるカード重複の整合性検証

これらはBGA側のサーバー実装で一元管理し、クライアントを信用しない。

### 8. バイクマスター

- Google Sheets、本番D1、リポジトリ内データの正式なマスターを一本化する
- 価格単位、カードID、画像URL、収録タイトル情報を統一する
- 4タイトルをゲームオプションまたは個別バージョンのどちらで扱うか決定する
- BGAプロジェクトへマスターを取り込む更新フローを設計する

### 9. 画像・商標・ライセンス

- Touring ManiaのBGA向けデジタル化許諾を確認する
- バイク写真、メーカー名、ロゴ、商品画像のBGA上での利用権を確認する
- Cloudflare R2の外部画像参照可否と、BGAプロジェクトへの同梱要否を確認する
- BGAおよび権利者の公開承認手順を確認する

### 10. 認証・周辺機能

以下はBGAアカウント・標準機能へ置き換えるか、BGA版では対象外とする。

- メール認証
- ゲストセッション
- マイガレージ
- 独自ユーザー戦績
- Cloudflare固有の環境変数、D1、R2運用

### 11. 翻訳と品質

- 表示文言をBGA翻訳システムへ移行する
- ソース内に残る文字化けした日本語を移植前に修復する
- 変数名、コメント、ログを英語中心へ整理する
- チュートリアル、ゲームヘルプ、リプレイ、ログ要件を確認する
- ルール判定の自動テストをBGA版でも用意する

## 推奨する最小プロトタイプ

最初から現行機能をすべて移植せず、以下に限定して検証する。

- 2人対人戦
- 1タイトルのみ
- 配札
- 宣言
- 1枚出し
- ドローとパス
- 場流れ
- 勝敗判定
- 再読み込みとリプレイ対応

プロトタイプでBGAのステート管理、手札秘匿、通知、カード表示が成立した後、
複数枚出し、縛り、3～4人戦、4タイトル対応を追加する。

## 完了条件

- BGA移植の可否と前提条件が文書化されている
- 権利・ライセンス上の公開条件が確認できている
- ゲームステート、DB、非公開情報、通知の設計案がある
- 最小プロトタイプの範囲と実装順序が決まっている
- 再利用するルール・データと再実装する範囲が明確になっている
- 次の実装Issueへ分割できる状態になっている
