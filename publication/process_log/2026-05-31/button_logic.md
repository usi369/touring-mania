# ボタン設計のロジック：触り心地（Tactility）の数値化

## 課題
標準的なウェブのボタンは「クリックされること」を目的としているが、ゲームのボタンは「押した感覚（フィードバック）」をユーザーに与える必要がある。
特にBalatroのようなゲームでは、ボタン一つ一つの「押し心地」が全体のクオリティ（Juiciness）を左右する。

## 戦略：3つのフィードバック層
1.  **視覚的（Hover）**: 
    - マウスを乗せた瞬間に、わずかに「発光（Glow）」させる。
    - ロジック：暗い背景に対して、ボタンが「アクティブなオブジェクト」であることを脳に認識させる。
2.  **物理的（Click/Tap）**: 
    - 押した瞬間に `scale: 0.95` 程度に縮小させる（押し込み）。
    - 離した瞬間に `spring` アニメーションで元のサイズよりわずかに大きく（`1.02` 程度）戻し、振動させる。
    - ロジック：現実世界の「バネ」の動きをシミュレートし、指への反動を視覚的に補完する。
3.  **状態の明示（Disabled）**: 
    - 選択不可（Banned）なボタンは、単にグレーアウトするだけでなく「ノイズ」や「赤い警告色」を混ぜる。
    - ロジック：ユーザーが「なぜ押せないのか」を即座に理解できるようにする。

## 実装のポイント（Framer Motion）
```tsx
<motion.button
  whileHover={{ scale: 1.02, boxShadow: "0 0 20px rgba(34,211,238,0.4)" }}
  whileTap={{ scale: 0.95 }}
  transition={{ type: "spring", stiffness: 400, damping: 10 }}
>
  押す
</motion.button>
```
この設定により、硬すぎず柔らかすぎない「心地よいバネ感」が生まれる。
